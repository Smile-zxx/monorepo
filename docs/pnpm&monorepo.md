
## ⚖️ Monorepo 的优缺点

### ✅ 优势

- **统一依赖管理**：所有包和应用共用一套依赖，避免重复安装和版本冲突，升级维护更简单
- **代码复用与共享**：不同包之间可以直接引用和复用代码，无需发布到 npm 或复制粘贴
- **原子化提交与协作**：可以一次性提交跨多个包的更改，方便团队协作和代码审查
- **一致的开发体验**：统一的构建、测试、发布流程，提升开发效率和一致性
- **更好的可维护性**：集中管理所有项目，便于追踪依赖关系和整体架构演进
- **提升 CI/CD 效率**：可以只针对变更的包进行构建和测试，节省时间和资源

### ❌ 缺点

- **初始配置复杂**：相比单一项目，monorepo 需要配置更多的工具和脚本来管理多个包和应用
- **构建和测试耗时增加**：随着项目规模扩大，构建和测试所有包可能会变慢，需要额外优化（如增量构建）
- **权限与发布管理复杂**：不同团队或成员对不同包的权限管理、独立发布等需求会变得更复杂
- **依赖关系易混乱**：包之间的依赖关系如果管理不当，容易出现循环依赖或依赖地狱问题
- **工具兼容性问题**：部分第三方工具或服务对 monorepo 支持不佳，可能需要额外适配
- **CI/CD 配置更繁琐**：持续集成和部署流程需要针对 monorepo 结构做更多定制化配置

## 🚀 pnpm 相比 yarn 和 npm 的优点

### 💾 磁盘空间占用更小

pnpm 采用"硬链接+内容寻址存储"的方式，所有依赖只在磁盘上存储一份，大幅减少 node_modules 体积，节省磁盘空间。

#### 链接机制说明

- **硬链接（Hard Link）**：硬链接是指向文件在磁盘上的实际数据（inode）的引用。多个硬链接指向同一个文件内容，删除其中任意一个链接，文件内容依然存在，只有所有硬链接都被删除后，文件内容才会被释放。硬链接不能跨分区，也不能链接目录。

- **软链接（符号链接，Symbolic Link）**：软链接是一个特殊的文件，内容是另一个文件的路径，相当于"快捷方式"。软链接可以跨分区，也可以链接目录。删除原文件后，软链接会失效（变成"死链"）。

### ⚡ 安装速度更快

pnpm 的依赖安装速度通常比 yarn 和 npm 更快，尤其是在多项目或 monorepo 场景下表现更优。

#### 安装更快的主要原因

1. **依赖复用与硬链接机制**：pnpm 采用全局内容寻址存储（store）和硬链接技术，所有依赖只需下载和解压一次，后续项目通过硬链接直接复用，无需重复复制文件，极大减少了磁盘 I/O 和安装时间

2. **并行化处理**：pnpm 在安装依赖时会并发执行多个任务（如下载、解压、链接），充分利用多核 CPU 资源，加快整体安装速度

3. **高效的缓存机制**：pnpm 会缓存已下载的依赖包，后续安装时直接从本地缓存获取，无需重新下载，尤其在 monorepo 或多项目环境下优势明显

4. **依赖解析优化**：pnpm 的依赖解析和锁定算法更高效，能快速确定依赖树结构，减少不必要的重复解析和冲突处理

5. **避免 node_modules 冗余**：pnpm 通过严格的依赖隔离和扁平化 node_modules 结构，减少了不必要的嵌套和冗余文件，提升了文件系统的访问效率

### 🔒 严格的依赖隔离

pnpm 默认不会将未声明的依赖提升到根目录，能有效避免幽灵依赖问题，保证依赖关系清晰可靠。

### 🏗️ 优秀的 monorepo 支持

pnpm 内置对 monorepo 的支持，无需额外工具即可高效管理多个包和应用。



## 🛠️ 如何初始化一个基于 pnpm 的 monorepo 项目

### 1. 初始化项目根目录

```bash
mkdir my-monorepo
cd my-monorepo
pnpm init
```

### 2. 创建 `pnpm-workspace.yaml` 文件

在项目根目录下新建 `pnpm-workspace.yaml`，内容如下：

```yaml
packages:
  - 'packages/*'
  - 'apps/*'
```

> 💡 你可以根据实际目录结构调整 `packages` 路径。

### 3. 创建子包或应用目录

```bash
mkdir -p packages/foo
mkdir -p apps/bar
```

### 4. 在每个子包/应用目录下初始化 package.json

```bash
cd packages/foo
pnpm init
cd ../../apps/bar
pnpm init
cd ../..
```

### 5. 在根目录安装依赖

```bash
pnpm install
```

### 6. （可选）配置开发工具

根据需要在根目录和各子包下添加配置文件：

- TypeScript
- ESLint
- Prettier
- Jest
- 等


## 📦 如何在 monorepo 中使用公共包

假设你已经在 `packages/common` 目录下创建了一个公共包（如 `common`），并在其 `package.json` 中正确设置了名称（如 `"name": "common"`）。

### 1. 在其他子包或应用中声明依赖

以 `apps/bar` 为例，进入该目录并执行：

```bash
pnpm add common --filter ./apps/bar
```

这会将 `common` 作为依赖添加到 `apps/bar` 的 `package.json` 中。

### 2. 在代码中直接导入使用

例如在 `apps/bar` 的某个文件中：

```javascript
import { someUtil } from 'common';

someUtil();
```

### 3. pnpm 的工作空间机制会自动链接本地包

只要 `common` 在 workspace 下，pnpm 会自动将其软链接到依赖它的包，无需发布到 npm。

### 4. 更新公共包后如何同步

当你修改了 `common` 包的内容后，只需在根目录下执行：

```bash
pnpm install
```

或者直接运行你的项目，pnpm 会自动确保依赖关系和链接是最新的。

> 💡 **总结**：在 monorepo 中，直接通过 `pnpm add 包名 --filter 目标包` 的方式即可在任意子包/应用中使用公共包，开发体验高效且一致。

## 🚀 如何将公共包发布到 npm

如果你希望将 monorepo 中的公共包发布到 npm 供外部项目使用，可以按照以下步骤操作：

### 1. 完善公共包的 `package.json` 配置

- 确保 `name` 字段唯一且符合 npm 命名规范（如 `@your-scope/common`）
- 设置好 `version`、`main`、`types` 等字段
- 移除 `"private": true`（如果有）

### 2. 构建公共包

进入公共包目录（如 `packages/common`），执行构建命令（如有）：

```bash
pnpm build
```

或者使用你配置的构建脚本。

### 3. 登录 npm 账号

如果还未登录 npm，请先执行：

```bash
npm login
```

### 4. 发布到 npm

在公共包目录下执行：

```bash
npm publish --access public
```

> 💡 如果是带有 scope 的包（如 `@your-scope/common`），需要加上 `--access public`。

### 5. 在其他项目中使用

发布成功后，可以在任何项目中通过 npm/yarn/pnpm 安装并使用该包：

```bash
pnpm add @your-scope/common
```

## ⚠️ 注意事项

- 发布前请确保 `.npmignore` 或 `files` 字段正确，避免不必要的文件被发布
- 每次发布前需更新 `version` 字段，遵循 [语义化版本](https://semver.org/lang/zh-CN/)
- 建议在本地测试包的构建和导出是否正常

这样，你就可以将 monorepo 中的公共包发布到 npm，供外部项目或团队成员直接使用了。
